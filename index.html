ILOP

Intent Logistics Orders Protocol. An open standard for how AI agents turn a person's intent into a completed real-world order, and prove it was done.

ILOP sits on top of MCP. MCP defines how an assistant talks to a service. ILOP defines what a trustworthy real-world order looks like once it does.

Six steps, every order

  1. QuoteThe exact all-in price, before anything exists.
  2. PrepareThe order is written up and checked; the person gets a link to read exactly what will be done.
  3. Approve and payThe person says yes to that exact total, on the link or in the chat.
  4. Carry outThe job goes to the partner who does the physical work. The card is charged only when they accept it.
  5. TrackOne small set of plain status words, from Quoted to Completed.
  6. Prove and repeatProof a third party can check, and the obvious next step in one click.

The promises every ILOP provider makes

  • Nothing is done or charged without the person's explicit yes to the exact total.
  • A changed price, document or destination cancels that yes.
  • Retrying never charges twice.
  • Nobody says "sent" or "done" before the fulfillment partner has accepted the job.
  • Every answer says plainly whether money was taken and whether the work happened.

How an agent finds a provider

Each provider publishes /.well-known/ilop.json, naming its actions, its MCP endpoint, the tools for each step and the kinds of proof it issues.

{
  "ilop_version": "0.1",
  "provider": { "name": "Piloxa", "url": "https://piloxa.com" },
  "mcp": { "url": "https://piloxa.com/mcp", "auth": "none" },
  "actions": [{ "id": "mail.certified.us",
    "proof_types": ["carrier_tracking", "return_receipt", "document_hash"] }],
  "tools": { "quote": "quote_certified_letter",
             "prepare": "prepare_certified_letter",
             "authorize": "authorize_certified_letter",
             "status": "get_certified_letter_status" }
}

What ILOP is not

ILOP does not define payments. It works with whichever agent-payment method the assistant supports, or with a provider-hosted approval page. It standardizes the part payment protocols leave out: carrying out a real-world service and proving it happened.
